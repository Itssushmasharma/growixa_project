## Why this task, not the other three that were also `READY`

After `GRX-FOUND-005` landed, four tasks became `READY`: `GRX-AUDIT-001`, `GRX-AUTH-001`,
`GRX-TEST-001`, `GRX-TEST-002`. Before picking one, I checked
[DATABASE_SCHEMA.md](../05-data/DATABASE_SCHEMA.md) and found `audit_logs.actor_user_id` is
an FK to `users.id` — so `GRX-AUDIT-001` can't actually be built before the `users` table
exists, even though the tracker only listed `GRX-FOUND-005` as its dependency (a real gap,
now fixed in the tracker — see below). Did `GRX-AUTH-001` first for that reason.

## Work completed

- **`apps/api/src/growixa_api/{roles,permissions,users}/models.py`** (new): SQLAlchemy 2.0
  models matching [DATABASE_SCHEMA.md](../05-data/DATABASE_SCHEMA.md) exactly —
  `Role`, `Permission` + `RolePermission`, `User` + `UserRole`. UUID PKs are generated
  application-side (`default=uuid.uuid4`) rather than via `gen_random_uuid()`, so no
  `pgcrypto` extension dependency. `email` uses `CITEXT` (case-insensitive, per the schema
  doc). `status` has a `CHECK (status IN ('ACTIVE','DISABLED'))` constraint. Split by module
  per [MODULE_BOUNDARIES.md](../04-architecture/MODULE_BOUNDARIES.md): `permissions` owns
  `role_permissions` (the doc says permissions "owns... role→permission mapping"); `users`
  owns `user_roles` (it has `assigned_by_user_id → users.id`). Only `models.py` per module —
  no `api/`/`services/`/`repositories/` yet, since there's no business logic for those
  layers to hold until `GRX-AUTH-002`/`GRX-RBAC-001`.
- **`migrations/env.py`**: now imports all three new model modules (for their side effect of
  registering tables on `Base.metadata`) so `--autogenerate` sees them.
- **Migration `d330e8b64b48`**: autogenerated the 5 `CREATE TABLE` statements (Alembic's
  dependency-aware ordering put `roles`/`permissions`/`users` before the two association
  tables correctly, no manual reordering needed), then hand-added:
  - `CREATE EXTENSION IF NOT EXISTS citext` before table creation (and `DROP EXTENSION IF
    EXISTS citext` in `downgrade()`, for a clean round-trip to empty).
  - Seed data for the 6 Sprint 1 roles, 6 permission codes, and the full 16-row
    `role_permissions` matrix, exactly per [RBAC.md](../08-security/RBAC.md). Used
    `sa.table()`/`op.bulk_insert()` proxies rather than importing the ORM models directly
    (Alembic's own recommended pattern — keeps this migration's meaning fixed even if the
    models change later). Seed UUIDs are fixed constants generated once (not randomized per
    migration run), so the migration is reproducible.
- **`apps/api/tests/test_auth_schema_seed.py`** (new): integration-tier test (real Postgres)
  asserting the *exact* set of role names, *exact* set of permission codes, and the *exact*
  role→permission matrix — not just row counts — after `alembic upgrade head`.
- **Fixed a tracker dependency gap**: `GRX-AUDIT-001`'s row listed only `GRX-FOUND-005` as a
  dependency; added `GRX-AUTH-001` (now marked done) since `audit_logs` FKs to `users.id`.

  `python -m growixa_api.cli.seed_first_admin` as landing "when `GRX-AUTH-001` ... is
  implemented," but no tracker task actually owns it, and it needs Argon2id password

  add later; not a migration-affecting change when it happens.
